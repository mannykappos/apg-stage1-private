## 9. Deviations, and every mistake

### Where stage 1 differs from the plan's wording (each stated in the test that covers it; for the reviewer to judge)

- **D1. The timeout measurement line** is printed as `TIMEOUT <id> cmd=… limit=… control_start=… control_end=…`. The plan's P1-F7 (R4) proposed the name `TIMING` as a builder proposal; R1 §2.6 fixes the content, not the name.
- **D2. f672's 300 s rerun is not kept.** The plan (AX-4 fix) says f672's rerun rule "stays as a way to settle a short-timeout case". The successor mutation tools take no `--timeout` option: each uses M10's default limit throughout (300 s for f672), so there is no short-timeout case to settle, and any timeout is `INDETERMINATE` (DP-2.1 (a)). The plan's f672 test expectation (INDETERMINATE on the successor) is met.
- **D3. `--batch` is refused outright** in `m8_mutants_s1` and the F-67 successors ("use --ids with exact ids"), with its `RUN_ERROR` and `RESULT` lines. The plan requires only that an out-of-range `--batch` (for example `0/4`) exit 2.
- **D4. A runner started from a working directory other than the root is refused** (`ENV_CWD`, exit 2). The plan's P1-F6 (R4) wording expects the run to go ahead with the root recorded; the start rule of T-0 (§2.8) makes it a run error, which is stricter.
- **D5. The interpreter-hash and disk-floor checks** are tested on the shared start sequence (`evkit.py --self-check`), not on a runner, and have no M10 half (M10 has neither check). Every runner calls the same start sequence and prints its interpreter's SHA-256; the 10 GB floor applies to every runner and every fresh copy.
- **D6. P4-B17's M10 marker:** M10's `ALL M6 CHECKS PASS` cannot be reached in this tree, because `run_m6_all`'s historical groups fail on clean M10 (W-1A); the M10 half shows the defect as the PASS of its 20 test groups that ran no test.
- **D7. P1-F5 (R5):** the failing file is made to fail through M10's CA07 mutant of `apg/canon.py`, not by editing `test_values.py`, because each test file's hash is pinned.
- **D8. The empty ingest corpus** is refused as `CASE_INVENTORY_MISMATCH … found=0 pinned=44` (R5 made the corpora `kind=cases` with pinned case inventories); the plan's P2-B8 wording says `EXPECTED_COUNT_MISMATCH`.
- **D9. The four fault runners other than `run_faults_s1`** have no test of their own for a failed reference control: they share `evkit.faults_main`, whose control is shown on `run_faults_s1`. They run in one process and start no child, so the timeout and crash cases do not arise for them.
- **D10. Twelve of the 19 wrappers have no test of their own;** each is proven by its full run in section 3 (both Pythons, the checker on every output).
